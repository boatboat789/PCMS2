# ตรวจสิ่งที่เกี่ยวข้องก่อนแก้ทุกครั้ง — ห้ามเดาแล้วแก้

กฎนี้ใช้กับทุกโปรเจกต์ใน workspace (user สั่งเน้น 2026-10-23: "ตรวจดูสิ่งที่เกี่ยวข้องก่อนแก้เสมอ อย่าพลาด")
เสริม `.claude/rules/core-behavior.md` ("think before coding, surgical changes") และ
`.claude/rules/verify-in-browser-not-only-tests.md` (ตรวจหลังแก้) — ไฟล์นี้คือขั้น "ตรวจก่อนแก้"

## บทเรียนจริง (LBMS 2026-10-23)

1. **ตัวกันส่งซ้ำ (H9) แก้ผิด 3 รอบ** — ผมเดากุญแจของ "งานซ้ำ" เอง (ProductionOrder+SendFrom → เพิ่ม LabNo)
   ทั้งที่กติกาจริงอยู่ในโค้ดข้างๆ แล้ว: รายการ "รอส่ง" ของหน้า PC/QA/Dye ซ่อนแถวที่มี `ImportDetail`
   สถานะ `Lab` ของ ProductionOrder เดียวกัน (ไม่นับ Reformula) — `DataFromSapTwoDaoImpl.leftJoinB`
   → ตัวกันซ้ำที่เขียนใหม่ต้องใช้กติกาเดียวกับที่ระบบใช้อยู่แล้ว ไม่ใช่กติกาที่ตัวเองคิด
2. **สับสนคำเฉพาะของ user** — "PO" = Purchase Order แต่ผมเรียกคอลัมน์ `ProductionOrder` ว่า PO ทั้ง session
3. **สคริปต์แปลงโค้ดจับผิดเมธอด** — regex ข้ามเมธอดเมื่อปีกกามีช่องว่างท้ายบรรทัด (จับได้เพราะคอมไพล์แตก
   ถ้าเงียบ = พลาดไปเลย) · แก้: แยกเมธอดด้วยการจับวงเล็บ ไม่ใช้ regex ข้ามบล็อก
4. **เปลี่ยนวิธีรับข้อมูลแล้วฟิลด์ที่ไม่ควรรับหลุดเข้ามา** — หน้าเว็บส่งทั้งแถวกลับมา โค้ดเดิมคัดเฉพาะฟิลด์ที่ใช้
   (whitelist) การผูก object ตรงๆ จะทำให้ฟิลด์ภายในถูกหยิบไปใช้เงียบๆ

## ต้องทำก่อนแก้ (เรียงตามลำดับ)

1. **หาว่าระบบทำเรื่องเดียวกันนี้ที่อื่นอยู่แล้วหรือไม่** (`grep` ชื่อตาราง/คอลัมน์/คำของ business) แล้วใช้กติกาเดียวกัน
   อย่าประดิษฐ์เกณฑ์ใหม่ โดยเฉพาะ "ตัวตน/กุญแจของงาน" "สถานะที่นับว่าเสร็จ/ซ้ำ"
2. **ไล่ผู้เรียกและผู้ถูกเรียก** ของสิ่งที่จะแก้ — รวม JS/JSP ที่ยิง endpoint นั้น (content-type, ฟิลด์ที่ส่ง, ผลที่อ่านกลับ)
3. **อย่าสรุปความหมายคำเฉพาะของ user เอง** (ชื่อย่อ รหัส สถานะ เช่น PO, LabNo, SaleSet, ImportId) —
   อ่านโค้ดจริง หรือถามสั้นๆ ก่อน
4. **ถ้ายังไม่แน่ใจ ถามก่อนแก้** — ไม่แก้แล้วค่อยย้อนทีหลัง (แก้ผิดซ้ำๆ เสียเวลา user มากกว่าถามหนึ่งครั้ง)
5. **เครื่องมือแก้เป็นชุด (สคริปต์/regex) ต้องทำให้ "ล้มดัง"** — ข้ามเมธอดที่ไม่เข้ารูปแบบแล้วรายงาน
   ไม่แก้มั่ว · รันกับไฟล์เดียวก่อนค่อยขยาย · ดู diff ทีละส่วน
6. **หลังแก้ตรวจด้วยของจริง** — คอมไพล์ + สคริปต์เทียบผลเก่า/ใหม่ + อ่าน diff · ถ้าตรวจกับ DB/เบราว์เซอร์ไม่ได้
   ให้บอกตรงๆ ว่ายังไม่ได้ตรวจ ไม่พูดว่าเสร็จ

## ห้ามทำ

- ห้ามเดากติกาธุรกิจแล้วเขียนเป็นโค้ดโดยไม่หาว่าระบบเดิมใช้อะไร
- ห้ามแก้ซ้ำหลายรอบโดยไม่หยุดไล่หาต้นเหตุ/กติกาเดิมหลังรอบที่สองผิด
- ห้ามบอกว่า "แก้แล้ว/ตรวจแล้ว" ถ้าตรวจแค่คอมไพล์ผ่าน (คอมไพล์ไม่รู้เรื่องกติกาธุรกิจ)

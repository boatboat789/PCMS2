แต่ `mvn test` เขียว 100% ตลอด — สาเหตุเป็น pattern ที่เกิดซ้ำได้กับ Java/Spring stack ใดก็ได้ในนี้

## เคสจริงที่เกิดขึ้นแล้ว

## ต้องทำ

**ทุกครั้งที่แก้/เพิ่มอะไรที่ผู้ใช้มองเห็นได้ ต้องยิงของจริงดูก่อนบอกว่าเสร็จ**

- หน้าเว็บ / ฟอร์ม / ปุ่ม → เปิดเบราว์เซอร์กดจริง อย่างน้อย 1 รอบต่อ endpoint ที่แตะ
- ไฟล์ที่ดาวน์โหลด → **โหลดไฟล์ออกมาเปิดดูจริง** ทั้งเนื้อหาและ HTTP header (ชื่อไฟล์ ชนิดไฟล์)
- endpoint ที่มี `{id}` → กดจริงอย่างน้อย 1 เส้น (จับเคส parameter names หาย)
- ทุกอย่างที่อ่าน collection ของ entity → ต้องมี `@Transactional` และยิง HTTP จริงยืนยัน
  เพราะ `spring.jpa.open-in-view=false`

## รูปแบบที่ "เทสจับไม่ได้โดยธรรมชาติ" — ให้ระวังเป็นพิเศษ

1. **สิ่งที่ container/framework จัดการให้ตอน runtime** — parameter names, transaction, session,
   HTTP header, content negotiation
2. **ความ "ไม่ซ้ำ" ข้ามเรคคอร์ด** — เลขที่เอกสาร เลขที่ใบ ลำดับที่ ถ้าไม่มี unique constraint ใน DB
   ก็ไม่มีอะไรฟ้องเลย → เขียนเทสเทียบ `distinct().count()` ให้ชัด
3. **ผลลัพธ์ที่เป็นไฟล์ไบนารี** — เทสอ่านค่าที่เราเพิ่งเขียนลงไปเองได้ผ่านเสมอ
   ต้องเทียบกับ**ไฟล์ตัวอย่างจากผู้ใช้จริง** ถึงจะมีความหมาย

## ห้ามทำ

- ❌ ห้ามบอกว่า "เสร็จแล้ว/ใช้งานได้" โดยมีแค่ผล `mvn test`
- ❌ ห้ามเชื่อว่า `@Transactional` ในเทสสะท้อนพฤติกรรมจริง — มันซ่อนบั๊ก lazy loading ทุกตัว
- ❌ ห้ามแก้ค่าที่คาดหวังในเทสให้ตรงกับโค้ด เมื่อเทสไม่ผ่าน — ตัวเลขจากไฟล์/เอกสารของผู้ใช้คือความจริง

## เพิ่มจากเคส PrepareTax 2026-10 (3 ข้อที่พลาดจริง)

- 🔴 **ห้าม commit ก่อน `mvn clean test` ผ่านทั้งชุด** — เคสจริง: ใส่เครื่องหมาย `"` ในค่า `th:text="..."` ของ Thymeleaf → หน้าแรกพังทุกเทส (`Attribute "+" appears more than once`)
  แต่ commit ไปก่อนแล้ว ต้องมี commit แก้ตามหลัง · ข้อความภาษาไทยในนิพจน์ให้ใช้ `'...'` ล้วน ห้ามมี `"` ซ้อน
- เทสพังแบบ `NoClassDefFoundError`/`Unable to find @SpringBootConfiguration` ทั้งชุด = `target/classes` ถูกคอมไพล์สลับ JDK/IDE auto-build → `mvn clean test` ใหม่ก่อนสรุปว่าโค้ดพัง
- **ข้อเท็จจริงของโลกจริง (ขนาดกระดาษ ชื่อไฟล์เครื่องพิมพ์ ฯลฯ)** — ตรวจที่ตัวงาน (PDF/ไฟล์จริง) เทียบกับข้อความบนหน้าจอ/คู่มือแยกกัน: เคสจริง PDF ถูก (22 ซม.) แต่ข้อความบนหน้า/คู่มือ 4 ที่เขียน 20.9 ซม.
  ทำให้ผู้ใช้เลือกวิธีพิมพ์ผิด · แก้ข้อความทุกที่พร้อมกัน (หน้าจอ + คู่มือ 2 ที่ตามกฎ sync) แล้วบอกทั้งกรณี "กระดาษตรงขนาด" และ "กระดาษเล็กกว่า"

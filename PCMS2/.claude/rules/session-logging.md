# Session Logging Rule

กฎนี้ใช้กับทุกโปรเจกต์ใน workspace — ไม่ใช่แค่ตอน user สั่ง "บันทึกงาน" ตอนจบ session เท่านั้น

## ต้องทำ

**ทำอะไรที่เป็นจุดสำคัญ → บันทึกลง `.md` file ของ project ทันที** อย่ารอให้ user สั่ง

"จุดสำคัญ" คือ:
- แก้บั๊กที่หา root cause เจอ (โดยเฉพาะบั๊กที่ทีแรกเข้าใจผิด แล้วแก้ถูกทีหลัง — บันทึก "บทเรียน" ไว้ด้วย)
- เพิ่ม feature / เปลี่ยน business logic
- ตัดสินใจเชิงสถาปัตยกรรม (เลือกวิธีนี้ ไม่เลือกวิธีนั้น เพราะอะไร)
- งานที่ยังไม่จบ (code-complete แต่รอ rebuild/deploy/test/SQL) — ต้องบันทึกว่าเหลืออะไร
- พบ constraint/gotcha ที่ไม่ obvious จากโค้ด (เช่น "ห้ามใช้ `mvn package` เพราะมี jar อ้างผ่าน Eclipse Build Path")

## บันทึกที่ไหน

1. **หาไฟล์ log ที่มีอยู่แล้วก่อนเสมอ** — pattern ที่ใช้ในหลายโปรเจกต์: `NEXT_SESSION.md` (log ต่อเนื่องท้าย session, เรียงใหม่สุดไว้บนสุด), หรือ `<FEATURE>_WORKLOG.md` แยกเฉพาะงานใหญ่
2. **ถ้าไม่มีไฟล์ไหนเข้าเกณฑ์ → สร้าง `NEXT_SESSION.md` ใหม่ที่ root ของ project** (ดู template โครงสร้างจาก `docs/decision-records/` หรือโปรเจกต์อื่นใน workspace ที่มีอยู่แล้วเป็นตัวอย่าง)
3. อย่าสร้างไฟล์ใหม่ซ้ำซ้อนกับที่มีอยู่แล้ว — ต่อท้าย/แทรกบนสุดของไฟล์เดิม

## รูปแบบ entry (อิงจาก convention ที่ใช้อยู่)

```markdown
## ✅/🔥/🔲 YYYY-MM-DD — ชื่องานสั้นๆ (สถานะ: code-complete / รอ deploy / done)

### อาการ / เป้าหมาย
[บริบทว่าทำไมต้องทำ]

### สาเหตุ (ถ้าเป็นบั๊ก)
[root cause จริง — ถ้าทีแรกเข้าใจผิดแล้วแก้ถูกทีหลัง ให้บันทึกทั้ง 2 เวอร์ชันสั้นๆ + บทเรียน]

### แก้ / ทำอะไร
[ไฟล์ที่แก้ + สรุป logic]

### 🔲 ครั้งหน้า
[สิ่งที่เหลือ: rebuild/deploy/SQL/functional test — เป็น checklist ที่เช็คได้จริง]
```

- ใช้ ✅ (เสร็จ) / 🔥 (กำลังทำ ยังไม่จบ) / 🔲 (ยังไม่เริ่ม) นำหน้าหัวข้อ ให้ scan เร็ว
- ระบุไฟล์ที่แก้แบบ path เต็ม ไม่ใช่แค่ชื่อไฟล์ลอยๆ
- ถ้ามีบั๊กที่ debug ผิดทางก่อน (เช่น เข้าใจว่าเป็นปัญหา deploy แต่จริงๆ เป็น logic bug) — บันทึกไว้เป็นบทเรียน อย่าลบทิ้ง เพื่อไม่ให้เข้าใจผิดซ้ำ

## ทำไมกฎนี้สำคัญ

โปรเจกต์เหล่านี้ไม่มี issue tracker ผูกกับ code (ดู `docs/database.md` — ไม่มี migration framework, ต้องรัน SQL มือ) → `.md` file ใน repo **คือ** ที่เดียวที่เก็บ context ระหว่าง session ถ้าไม่บันทึก งานที่ "code-complete รอ deploy" จะหายไปกับ session ถัดไป

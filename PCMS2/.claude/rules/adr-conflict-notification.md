# ADR Conflict Notification Rule

กฎนี้ใช้กับทุกโปรเจกต์ (เพิ่ม 2026-08-21 ตามคำสั่ง user)

## ต้องทำ

- **ก่อนเขียนโค้ด/ตัดสินใจอะไรก็ตามที่ขัดกับ ADR ที่มีอยู่แล้วใน `docs/decision-records/`** (หรือ ADR
  เทียบเท่าของโปรเจกต์อื่นที่ไม่มีโฟลเดอร์นี้ตรงๆ) — **ต้องหยุดแล้วแจ้ง user ก่อนเสมอ** ห้ามเดินหน้าทำเงียบๆ
  โดยคิดว่า ADR เดิม "คงล้าสมัยแล้ว" หรือ "ไม่น่าเกี่ยวกับเคสนี้"
- บอก user ให้ชัดว่า **ขัดกับ ADR ไหน ข้อไหน** และ **ขัดยังไง** (สรุปสั้นๆ พอให้ user ตัดสินใจได้ทันที
  ไม่ต้องเปิดไฟล์ ADR เอง)
- ถ้าไม่แน่ใจว่า "ขัด" จริงหรือแค่ "เกี่ยวข้อง" — ให้แจ้งเช่นกัน (false positive ปลอดภัยกว่า false negative)

## สิทธิ์ยกเลิก

- **User มีสิทธิ์สูงสุดในการสั่งข้าม ADR ได้เสมอ** — เมื่อ user ยืนยันให้ทำต่อทั้งที่ขัด ADR ให้ทำตาม
  แล้วบันทึกการตัดสินใจนี้ไว้ (อัปเดต ADR เดิม หรือเพิ่มบันทึกในเอกสารโปรเจกต์ตาม
  `.claude/rules/session-logging.md`) เพื่อไม่ให้ session ถัดไปเข้าใจผิดว่ายังต้องทำตาม ADR เดิมอยู่

## ทำไมกฎนี้สำคัญ

ADR คือการตัดสินใจเชิงสถาปัตยกรรมที่ผ่านการคิดมาแล้ว การขัดโดยไม่แจ้งเสี่ยงทำลายเหตุผลเดิมโดยที่ user
ไม่รู้ตัว — แต่ user ก็ยังเป็นคนตัดสินใจสุดท้ายได้เสมอว่าจะข้ามหรือไม่ ไม่ใช่ Claude ตัดสินใจเอง

⚠️ **หมายเหตุ**: ไฟล์นี้อยู่ใน template repo — โปรเจกต์อื่นที่มีอยู่แล้ว (PCMS2/SFC/PPMM2/Dyeing/LBMS/...)
ต้อง copy ไฟล์นี้ไปใส่ `.claude/rules/` ของแต่ละโปรเจกต์เองด้วย ไม่ auto-sync (ดู [[feedback_user_manual_visual_over_text]] ที่เจอปัญหาเดียวกันมาก่อน)

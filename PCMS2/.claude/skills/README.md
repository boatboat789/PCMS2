# skills/ — Skills (ยังไม่ได้ใช้งาน)

โฟลเดอร์นี้ยังว่างอยู่ — scaffold ไว้ล่วงหน้า (template กลาง — copy ไปทุกโปรเจกต์ในเวิร์กสเปซ)

## Skill คืออะไร ต่างจาก agent (`.claude/agents/`) และ command ยังไง

`.claude/agents/` = **sub-agent** — รันแยก context ของตัวเอง มี tool/model กำหนดเฉพาะตัว เรียกผ่าน
Task tool หรือให้ Claude เลือกเรียกเองตามคำอธิบาย (บางโปรเจกต์ เช่น DyeingRecord มี agent เฉพาะทาง
อยู่แล้ว เช่น scout/planner/backend/frontend/verify แยกตามขนาดงาน — ดูตัวอย่างได้ที่นั่น)

**Skill** เป็นคนละอย่าง — เป็นชุดขั้นตอนสำเร็จรูป (อาจมีสคริปต์แนบด้วย) ที่ **โหลดเข้ามาในบทสนทนาปัจจุบัน**
เมื่อเรียกใช้ (ไม่ใช่รันแยก context แบบ agent) เหมาะกับงานที่ทำซ้ำๆ แบบมีขั้นตอนตายตัวในโปรเจกต์นั้น เช่น
"ตรวจ maxlength ทุก field ก่อน commit" (ตรงกับ `.claude/rules/input-validation.md` ที่มีอยู่ทุกโปรเจกต์)
หรือ "audit UI/UX ทีละหน้า" (บางโปรเจกต์มี prompt เฉพาะทางสำหรับเรื่องนี้อยู่แล้ว)

## โครงสร้างไฟล์ต่อ 1 skill

```
skills/
  ชื่อ-skill/
    SKILL.md          ← คำอธิบาย + ขั้นตอน (บังคับ)
    สคริปต์เสริม.sh    ← ถ้ามี (ไม่บังคับ)
```

**ยังไม่มี skill จริงในนี้** — เป็น template กลาง รอแต่ละโปรเจกต์ตัดสินใจว่างานไหนทำซ้ำบ่อยพอ
จะคุ้มทำเป็น skill (ตัวเลือกที่น่าจะเข้าเกณฑ์ในทุกโปรเจกต์: input-validation checklist และ
session-logging ตาม `.claude/rules/` ที่มีอยู่แล้ว)

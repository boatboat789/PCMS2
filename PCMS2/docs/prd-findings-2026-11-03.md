## ภาคผนวก: Prod. Qty "ควรเป็นยอดสุทธิ (หักพ่วง/สวม) เสมอ" — หลักฐานจากโค้ดและข้อมูล (ตอบข้อ 1 แทนความจำ)

**ความหมายที่ผู้ใช้เห็น (ตามสูตรสุทธิ):** แถว Main แสดง "ปริมาณที่เหลือสำหรับ SO นี้" ส่วนที่แบ่งให้ SO อื่นไปอยู่ที่แถวย่อย (SUB) ของ SO นั้น — เมื่อค้นเฉพาะลูกค้า A ก็ยังต้องเห็นยอดสุทธิของ A (ไม่ใช่ยอดรวมที่รวมส่วนของลูกค้า B)

**ทางแก้ที่เสนอ (ยังไม่ได้ทำ):** ใน `PCMSSqlService.createTempForMainAndWaitLotFiltered` เปลี่ยนเงื่อนไขขอบเขตของ `#tmpSumVolOP` และ `#tmpSumVolRP` จาก "SO/line ปลายทางอยู่ใน `#tempMainSale`" เป็น "PO อยู่ในชุด PO ของ sale line ที่ค้น" (`ProductionOrder IN (SELECT fsp.ProductionOrder FROM FromSapMainProd fsp JOIN #tempMainSale ms ON ms.SaleOrder=fsp.SaleOrder AND ms.SaleLine=fsp.SaleLine)`; สวมใช้ `ProductionOrderRP`) — ตัดแถวได้เท่าเดิมตามเจตนา perf แต่ผลไม่ขึ้นกับตัวกรอง · วิธีพิสูจน์หลังแก้: รัน `OrigVsCurrentDetailCheck` ด้วยตัวกรองหลายแบบ (G TECH อย่างเดียว vs +TW/PLC) ค่าแถวเดียวกันต้องเท่ากัน และ A/B บน PRD ต้องเหลือ `volumn` ต่างจากโค้ดไม่กรอง = 0

**สิ่งที่ยังเป็น 🟡 จริงๆ:** มีแค่ "เจ้าของงานยืนยันว่าความหมายสุทธิถูกต้อง" — โค้ดและประวัติชี้ทางนี้ชัดเจน
